# HLA1587: upload into the selected source row

An admin identifies a stale or overdue source on `/sources`, selects a CSV, XLSX or JSON file on that named row, sees a source-pinned preview and explicitly uploads to that same source. The page stays at `/sources`; the same row refreshes to show the actual returned run and truthful observed freshness, while sibling source rows remain unchanged. Shared formats do not identify which account the file belongs to: explain that ambiguity and preserve the user's selected source. Detection is advisory; absent or different primary detection must not redirect the upload or reject an otherwise valid pinned file. An old or wrong-bound preview cannot enable mutation; a file change invalidates its earlier preview. A cancelled old request or a deliberately late old response must not override the newest file. The named submit control and outcomes are accessible, with outcome announcements in an `aria-live` region. An in-flight upload blocks duplicate submit, and uncertain mutations are never automatically retried.

Preserve the existing configured upload and its CSV/XLSX/JSON normalization, `/upload` 303/summary flow, API and authorization boundaries. Readers still redirect from `/sources`, and the existing operator freshness 403 remains truthful; do not widen access. An empty identifier is unavailable. Source IDs are opaque: slash, percent and Unicode round-trip exactly once without trimming or repeated decoding. Do not invent manual-upload restrictions from free-form source type or transport values. Without JavaScript, native row controls cannot mutate without the preflight gate; a safe form or file selector is not itself prohibited.

## Bound BFF response contract

`POST /sources/{source_asset_id}/dry-run` and `/upload` return JSON without redirects. They pin the exactly once decoded path ID and drop multipart binding overrides, including smuggled builtin upload paths. Each constructs fresh multipart data: dry-run sends the file, pinned ID and `/upload/configured-csv`; upload sends the file, pinned ID and trimmed source name. A missing file returns 400 without an upstream call. Cookie and CSRF handling preserve the existing boundary. Dry-run returns `ready`, `target` (`source_asset_id`, `upload_path`, `confidence_label`), `row_count`, `issues`, and `detection.format`. Upload returns `outcome`, `message`, and when applicable `run_id`, `status`, `row_count`, `issues`, `promotion`, `freshness_state`, `observation`, and `observed_latest_run_id`. Promotion permits only `facts_loaded`, `marts_refreshed`, `publication_keys`, and `skipped`; issue objects permit only `code`, `message`, `column`, and `row_number` with validated fields.

A 201 with receipt and matching actual run context is `landed` when the observed row matches; a failed context reread is `landed_unconfirmed`. A contradictory context is `identity_mismatch`: retain the actual receipt ID and HTTP status, use `Run recorded; source identity differs.`, and do not imply the selected source, its current freshness or publication is verified. If context matches but the latest row is superseded or missing, retain the receipt, expose `observation` as `superseded` or `missing`, expose the independently observed latest ID and freshness or null, and use `Run landed. The observed latest run differs.` or `Run landed. The source freshness row was not returned.` A superseding run is an observation, not this receipt's identity or proof of publication.

Receipt-bearing 400 and 409 responses require the same actual run-context read. Matching identity yields `rejected` or `duplicate`; contradictory identity yields `identity_mismatch`; unreadable identity yields `identity_unconfirmed` and `Run recorded; source identity could not be confirmed.` Preserve the original HTTP status and receipt in each case; neither latter label asserts no mutation or successful landing. This is distinct from 201 `landed_unconfirmed`. Upstream 401 and 403 may be `auth_required` and `forbidden`. Without an authoritative receipt, preserve upstream 400, 404 or 422 and return `outcome_unknown` with `Upload outcome could not be confirmed.` Optional `observation: observed`, `observed_latest_run_id`, and `freshness_state` are supplied together only as an independently read observation, never as evidence that no run was created or that a changed run belongs to this request. Malformed/non-JSON success, a success without a receipt, upstream 5xx, or transport failure returns 502 `outcome_unknown`; do not retry. Dry-run preserves meaningful upstream error status and maps transport failure to 502 without exposing diagnostics.

Normalize unrecognized issue codes to `unknown` with `Validation issue.` Known issue codes use the fixed safe templates enumerated in the acceptance test, including `File already exists.` for `duplicate_file` and `Required value missing for column 'amount'.` for a validated missing `amount` value. A displayed column is absent or validated, and a row number is a bounded positive integer. Never echo arbitrary upstream detail/error, exception text, stack, raw or manifest path, hash, unvalidated structured field, promotion skip reason or unrelated diagnostic. Observed freshness is not proof of publication; never claim `current` for an unconfigured schedule.
