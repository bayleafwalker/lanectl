## Proposed minimal BFF contract

Both `POST /sources/{source_asset_id}/dry-run` and `/upload` return JSON without redirects, use the exactly once decoded path identity as authoritative, and drop multipart binding overrides. Dry-run returns `ready`, `target` (`source_asset_id`, `upload_path`, `confidence_label`), `row_count`, `issues`, and `detection.format`. Upload returns `outcome`, `message`, and when applicable `run_id`, `status`, `row_count`, `issues`, `promotion`, `freshness_state`, `observation`, and `observed_latest_run_id`. Promotion permits only `facts_loaded`, `marts_refreshed`, `publication_keys`, and `skipped`. An issue permits only `code`, `message`, `column`, and `row_number` with validated structured fields.

Without a direct authoritative run receipt, a mutation has `outcome_unknown`; preserve an upstream 400, 404 or 422 status, never infer no effects or request attribution from a latest pointer, and never retry automatically. Auth 401/403 may use role-truthful categories. The generic receipt-free message is `Upload outcome could not be confirmed.` With a receipt, identify the run through its actual source context. A contradictory context is `identity_mismatch`. A matching context with missing or superseded freshness row is not mismatch: `observation` is `missing` or `superseded`, `observed_latest_run_id` is null or the independently observed ID, and `freshness_state` is null or that observed row's state. Messages are `Run landed. The source freshness row was not returned.` or `Run landed. The observed latest run differs.` A receipt with an unreadable context is `landed_unconfirmed`; no statement implies that a superseded receipt itself is current. `observation: observed` and the actual observed pointer may be returned after receipt-free outcomes, but do not establish causation. Freshness does not prove publication.

Unknown issues use `Validation issue.` Known `missing_required_value` with validated column `amount` uses `Required value missing for column 'amount'.` The fixed safe templates for the remaining known codes are enumerated in `_json_response`; duplicate files use `File already exists.` A column is either absent or validated for display, and a row number is a bounded positive integer. Unknown issue messages, upstream detail/error strings, transport exceptions, stack traces, paths, hashes, unvalidated structured fields, promotion skip reasons and other diagnostics are never echoed. CSV, XLSX and JSON remain supported independently of detection; an empty source ID is unavailable and opaque slash/percent/Unicode IDs must round-trip exactly. Named-row user choice and pinned preflight cannot be overridden by detection or smuggled fields.

Expected case IDs are enumerated in the readable `EXPECTED_CASES` tuple. R2 adds independently validated unique success fixtures, wrong-bound real-preflight fault controls, receipt-to-displayed-href identity, response sanitization and freshness observation falsifiers, exact process-group failure controls, and real native-browser forced-failure cleanup. Any setup, timeout, source-binding or cleanup problem is infrastructure failure, not a semantic base red.
