Prior native suggestions to edit package scripts or omit Python tests are superseded by the integration-owner disposition. Candidate must provide a production-used `apps/web/frontend/lib/onboarding-checklist-state.mjs` exporting `freshDatasetNames(rows, nowMs)`, `checklistProgress(sources, freshDatasets)` (including `activeCount`, `requiredDone`, `requiredTotal`, `allCoreActive`) and `checklistView({dismissed,compact,userExpanded,allCoreActive})` returning `hidden`, `badge`, or `full`. The component and page consume corresponding actual functions. Worker tests and Python wrapper count toward M700; no package/Makefile/lock changes.

Run `qualify_unit.py --checkout <clean exact-candidate> --wrapper <worker pytest wrapper path> --output <new evidence directory>` using Node 20. This runs seven named independent built-in Node tests against the actual helper first and rejects zero tests, skips, todo, missing tool, parse/import failures or a failing real helper. It hashes the candidate helper before and after. It generates four closed ESM fault wrappers importing that exact helper by file URL: freshness adds equality-boundary rows after calling the real function; required marks source objects required before calling real progress; override clears userExpanded before calling real view; dismissal clears dismissed before calling real view. Other exports delegate unchanged. Each wrapper must produce the specific named assertion failure, not setup/import/parse failure. The candidate pytest wrapper must pass, a failing Node shim must prove it executes Node, and the actual wrapper must reject each of the four bound faults in an owned candidate copy with assertion evidence (no import or parse failure). A version-only wrapper is rejected. All output and exits are persisted before assertions.

Run the frozen real-component acceptance separately against the clean candidate and preserve its evidence. Then run `run_wiring_probe.py --checkout <clean exact-candidate> --baseline-evidence <candidate acceptance evidence> --output <new evidence directory>`. Before allocating a worktree or launching Next it compares the complete baseline fingerprint, modes and symlinks to the exact clean candidate and rejects stale evidence. It then creates an owned detached worktree at the actual SHA, copies the actual helper byte-identically beside its original path, substitutes a closed override wrapper at that path, runs the frozen real component suite, and invokes `qualify_wiring.py`. The oracle requires a green 16-case baseline, exactly one changed tracked path between evidence snapshots (the helper), unchanged controls, and an actual Expand post-click heading failure under the bound wrapper. It verifies candidate hash/status invariance and removes its owned worktree in `finally`. Actual candidate unit/mutations/wiring proof remain UNOBSERVED until a candidate exists. Do not substitute the synthetic oracle selftest for this proof.

The component fixture does not prove real-page role, as-of, timestamp wiring, or accessibility. These are separate required real-page and accessibility checks. Run existing 55 matched Ubuntu Playwright checks with unchanged tolerances and full make verify-fast. Actual inner completion and all output must be retained.
