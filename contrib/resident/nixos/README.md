# Isolated resident execution on devbox or workstation

This contribution supplies an opt-in NixOS deployment for the real
`lanectl resident run` admission/checkpoint protocol. It includes two examples:

| Deployment | Executor | Model route | GPU owner |
| --- | --- | --- | --- |
| Devbox | Dedicated `resident-worker` system account | OpenCode Go, `opencode-go/deepseek-v4.1-flash` | Provider |
| Workstation | Dedicated `resident-worker` system account on the workstation | Existing authenticated peer, `local/worker-fast` | Existing workstation llama-swap |

The workstation example runs the **whole bounded episode on workstation**.
Its files, credentials and process identity are separate from the normal user.
It does not create a competing inference engine or move the desktop GPU into a
guest. A devbox executor can also select the local model route after the narrow
cross-host egress/peer grant described below.

**Status:** source implementation and unprivileged bridge tests exist. Nix is
not available in the implementation workspace, and neither target host was
accessed. Nix evaluation/build, actual namespace/cgroup enforcement, OpenCode
compatibility, GPU/model generation and end-to-end qualification are outstanding
gates. The examples default both `enable` and `executionEnabled` to false. No
qualification receipt is generated by this module.

## Installed boundary

`lanectl-resident-episode.service` is a protected root dispatcher. It reads one
root-protected admission request, invokes the existing resident CLI, and owns
the local receipt log, fencing state and immutable checkpoint objects. Root is
used only for the trusted coordinator and the fixed systemd bridge; the model
does not receive a root shell.

The SHA-bound launcher starts a fixed transient
`lanectl-resident-tools.service` under `resident-worker`, which has no login and
only its private group. The tool service has:

- Private writable workspace and native runtime directories; disjoint protected
  control state.
- Read-only system/Nix configuration, inaccessible homes, private `/run` and
  `/var`, private `/tmp`, private IPC and no physical devices. Only the workspace
  and native runtime are rebound into the private `/var`.
- No normal-user home, desktop bus, SSH agent, Docker/libvirt socket, source
  checkout, NAS mount or gateway credential directory.
- Its own network namespace and loopback interface, including a separate
  abstract Unix socket namespace. Host pathname sockets are hidden, including
  the Nix daemon under `/nix/var`. Its own native Unix/PTY IPC remains available.
- An empty capability set, no namespace/cgroup delegation, no privilege gain,
  restricted kernel operations and explicit CPU/RAM/process/wall-time bounds.
- One explicit read-only bind of the protected model capability socket. The
  native launcher relays its own `127.0.0.1:18021` to that fixed Unix socket.
  There is no worker network interface/route to host DNS, WAN, LAN, raw model
  port `8020`, or unrelated host-loopback services.

Systemd 257 or later is required. `PrivateTmp=disconnected` backs temporary
storage with a private tmpfs rather than the host's shared temporary disk;
those pages must be accounted against the tool memory cgroup on the target.

The worker does not own its launcher, native profile, OpenCode configuration,
qualification receipt, gateway policy or coordinator state. Exact immutable
Nix-store paths are embedded in the generated launcher; their changes alter
its SHA and the qualification recipe. All installed Python module invocations
use `-I` to exclude the writable working directory and environment from Python
module discovery. The pinned Python package must pass isolated import checks;
never work around a missing import by enabling worker-controlled `PYTHONPATH`.

`lanectl-resident-model.service` runs as **another** private account,
`resident-model`. Only it receives `upstream-token` through systemd
`LoadCredential`. The gateway selects exactly one model/origin, bounds requests
and serializes inference. Its writable request ledger is separate from tools.
The Go example sets an explicit persistent request allowance. Local inference
has no request/spend allowance, while concurrency and physical resource bounds
remain in force. Route failures do not select a paid fallback.

PID1 owns `lanectl-resident-model.socket` at
`/run/lanectl-resident-model/model.sock`. The socket is owned by `resident-model`,
group `resident-worker`, mode `0660`; its parent is root-owned and not writable
by either worker or normal user. The gateway accepts the inherited socket only
after validating systemd's activation identity. The worker can connect to this
capability but cannot replace it, change its policy or read its upstream token.
It receives no host TCP listener. Ordinary users outside the worker group
cannot connect to the capability socket.

This composition supports OpenCode's private HTTP server on an ephemeral
loopback port and its native Unix IPC inside the isolated network namespace.
Allowing the worker arbitrary **host** loopback ports would expose unrelated
services; the private namespace avoids that expansion.

The worker has no direct memory-service credential or arbitrary memory write
API in this deployment. AgentOps prepares admitted context and consumes
checkpoint evidence through its own memory policy.

### Cleanup is part of the receipt

The tool process is a separate systemd cgroup, so killing the launcher's process
group alone is insufficient. The profile includes both `cleanup_argv` and
`cleanup_executable_sha256`. The runner invokes that protected hook **before
checkpointing**, including after cancellation/SIGKILL, and retains uncertain
execution if it cannot establish cleanup. The hook stops the fixed service and
checks both its inactive state and the recursive cgroup `populated` flag.
`BindsTo`/`PartOf`, the tool runtime deadline and coordinator `ExecStopPost`
provide additional crash/stop cleanup. No recursive `chown` touches agent files:
only the exact newly created empty episode HOME is handed over through held
directory descriptors that refuse symlinks.

The coordinator intentionally uses systemd `Type=exec`, despite doing one
bounded invocation. `Type=oneshot` would deadlock a tool unit ordered after a
coordinator that was still waiting to finish its start operation.

## Import into the actual host owner

At inspection, the available `gitops-nixos` mirror revision was
`56a90506fbe3e71de49aa44655affdf266bdafae`. Its workstation entry imports
`modules/system/llm-inference.nix`; the vendored model configuration there is the
declarative serving owner. `local-inference` is the design/measurement source.
These observations do not establish the live host generation.

Pin a reviewed lanectl revision in the host flake; do not import a floating
branch or a worker-writable checkout:

```nix
inputs.lanectl-src = {
  url = "github:bayleafwalker/lanectl/REPLACE_WITH_REVIEWED_COMMIT";
  flake = false;
};
```

Pass `lanectlSrc = inputs.lanectl-src` through `specialArgs`. Import
`module.nix` and one example directly from the pinned source, or vendor this
directory with an explicit source revision. The workstation example also
requires `residentModelPeerAddress` (the exact SAN-matching numeric address) and
`residentModelPeerCertificate`, the **public** certificate/CA file already
trusted for the peer, as `specialArgs` values. Keep actual private addresses in
the private host owner. Never include its TLS
private key or an upstream token in Nix strings/store files.

```nix
imports = [
  "${lanectlSrc}/contrib/resident/nixos/module.nix"
  "${lanectlSrc}/contrib/resident/nixos/workstation.example.nix"
];

services.lanectlResident.enable = true;
# Keep executionEnabled false until preparing a commissioning candidate.
```

`package.nix` packages the pinned source with its resident protocol/adapter
tests and import checks. The complete suite also needs a real systemd user bus
and is a separate **required** target-host/CI gate; a package build does not
waive it. No existing test is weakened. The host's pinned
OpenCode package must actually be version 2.2.3 or later; native execution checks
that version and the exact executable hash. Select a known pinned package if
the host's `pkgs.opencode` is older.

Use the existing SOPS/credential owner to provide either:

```text
/run/secrets/resident-opencode-go-token
/run/secrets/resident-local-model-peer-token
```

These are file paths only. The secret should be root-owned and mode `0400` or
`0600`; PID1 passes a private copy to the gateway. Do not copy a normal-user
OpenCode authentication cache into the worker or reuse another client's peer token.

`eventStateDir` is explicit because it selects the episode receipt authority.
The examples describe a separately commissioned local pilot log. If the chosen
host already selects a served event backend for this owner, retain that
selection: the resident pilot refuses it. Creating a fresh directory or
deleting `backend.json` to evade the refusal is not migration.

## Model peer and firewall integration

The existing peer at `https://MODEL_PEER_ADDRESS:8021/v1` permits fixed chat/responses
routes, TLS and bearer authentication. Its source configuration currently
allows cluster worker CIDRs, not a resident principal. Before local route
activation, the host owner must introduce an independent resident credential
and exact source grant. Workstation-local HTTPS to its own LAN address also
needs the source address observed on that path admitted. Preserve existing
client grants and certificate identity.

The existing single-token peer must be extended for separate principals, or a
second authenticated **peer listener** can serve the same loopback backend.
Update the configured port if that listener differs. This is not a second GPU
model router. The module does not silently share the existing bearer or disable
certificate validation to make a connection succeed.

On nftables hosts the module registers its UID table with
`networking.nftables.tables`, so a host ruleset reload retains it. On an
iptables workstation it installs an independent nft table with an atomic batch
and a service bound to the protected execution chain. It deliberately does not
enable NixOS's global nftables backend: the inspected model-peer module asserts
its iptables ingress implementation. Both backends need real reload/negative
tests on the target.

### Devbox using the workstation model

The inspected `agent-egress.nix` accepts `allowedLanHosts` as whole IPs/CIDRs.
Adding the workstation there would permit every workstation port at that
layer. Propose a narrow option in that module instead, while preserving its
current rule order and default-deny private-network behavior:

```nix
# New option in profiles.agentEgress:
allowedTcpDestinations = lib.mkOption {
  type = lib.types.listOf (lib.types.submodule {
    options = {
      address = lib.mkOption { type = lib.types.str; };
      port = lib.mkOption { type = lib.types.ints.between 1 65535; };
    };
  });
  default = [ ];
};

# Render before the private_cidrs drop in its existing output chain:
${lib.concatMapStringsSep "\n" (destination:
  "ip daddr ${destination.address} tcp dport ${toString destination.port} accept"
) cfg.allowedTcpDestinations}

# Host selection (adjust port only for the independently authenticated peer):
profiles.agentEgress.allowedTcpDestinations = [
  # Documentation address only; substitute the exact private host-owned address.
  { address = "192.0.2.55"; port = 8021; }
];
```

The new module's `resident-model` UID rule independently restricts that account
to the selected peer port. The worker has its own network namespace and reaches
the gateway only through the exact capability socket bind; the host's worker
UID rule additionally rejects host-network traffic. An accept in one nft base
chain does not override a later chain's drop,
so the existing devbox egress owner must explicitly admit this destination.
Do not edit/commit that private host repository before its required Nix checks.

## Admission and commissioning

The existing protected work/trigger owner writes these files atomically under
`/var/lib/lanectl-resident-control/inbox`, owned by root and non-writable by the
worker:

```json
{
  "schema": "lanectl.resident-admission/v1",
  "wake_id": "owner-event-0001",
  "generation": 1,
  "work_ref": "stories#1",
  "context": "/var/lib/lanectl-resident-control/inbox/context.json",
  "context_sha256": "REPLACE_WITH_EXACT_CONTEXT_FILE_SHA256",
  "source_recheck": "/var/lib/lanectl-resident-control/inbox/recheck.json",
  "source_recheck_sha256": "REPLACE_WITH_EXACT_RECEIPT_FILE_SHA256"
}
```

The request file is named `request.json`. The actual context and source-recheck
schemas are documented in `docs/resident-episodes.md`. The source observation
expires within 60 seconds; publish it immediately before admitted execution,
not when configuring the host hours earlier. Request hashes and safe paths are
checked, and only the fixed `resident run` arguments are constructed. The owner
starts one episode with:

```sh
sudo systemctl start lanectl-resident-episode.service
sudo journalctl -u lanectl-resident-episode.service --since '-10 min' --no-pager
```

There is no timer, polling daemon, self-issued wake or external-effect grant in
this module. Subsequent wakes remain with the existing owner. A result may
propose continuation but cannot start another privileged service.

To obtain a commissioning recipe, build/deploy the candidate with
`executionEnabled = true` while its qualification receipt is absent or invalid;
the runner still refuses execution. Use `resident describe` with the generated
profile. After actual boundary/model/source/budget probes, the protected
commissioning owner installs a matching receipt and records its exact SHA in
`qualificationSha256`. That field is excluded from the recipe, so installing
the receipt does not cause a circular digest. Any runtime/route change still
requires fresh qualification. Do not turn all receipt booleans on based on this
source file.

## Required validation

These checks are **outstanding**, not a record of successful deployment:

1. In the host GitOps checkout, before committing:

   ```sh
   nix flake check
   nix build .#nixosConfigurations.devbox.config.system.build.toplevel
   nix build .#nixosConfigurations.workstation.config.system.build.toplevel
   ./scripts/deploy-host.sh --host devbox --target-host devbox-deploy --dry-run
   ./scripts/deploy-host.sh --host workstation --dry-run
   ```

   In the pinned lanectl checkout on a host with the required systemd sandbox,
   `uv run pytest -q` must also pass. That full gate did not pass in the cloud
   implementation environment, whose user-scope systemd bus is unavailable.

2. Verify the pinned interpreter in isolated mode before activation:

   ```sh
   resident_python="$(nix eval --raw .#nixosConfigurations.workstation.config.services.lanectlResident.python)/bin/python"
   "$resident_python" -I -c 'import lanectl.resident, lanectl.resident_native, lanectl.resident_gateway, lanectl.resident_systemd'
   ```

   A Python environment that relies on an ignored environment path must be
   packaged correctly. Do not drop `-I`, add the current directory, or restore
   inherited `PYTHONPATH` as an import workaround.

3. Observe the real host and unit properties, avoiding environment/secret dumps:

   ```sh
   hostnamectl --static
   readlink -f /run/current-system
   nixos-version
   systemctl show lanectl-resident-tools.service \
     -p User -p Group -p ControlGroup -p ProtectHome -p ProtectSystem \
     -p PrivateDevices -p PrivateIPC -p PrivateNetwork -p BindReadOnlyPaths \
     -p SystemCallFilter -p MemoryMax -p TasksMax -p RuntimeMaxUSec
   sudo nft list table inet lanectl_resident
   ```

4. From a protected commissioning fixture in the exact tool boundary, observe
   refusal of normal-user home reads, Docker/libvirt/session sockets, abstract
   **host** Unix sockets, control-state writes, provider credential reads,
   DNS/WAN/LAN traffic and unrelated host-loopback ports. Prove the worker's
   private loopback/native IPC works and another ordinary UID cannot connect
   to the host model capability socket. A service-file inspection alone does
   not prove namespace/seccomp/firewall availability.

5. Run the actual pinned OpenCode harness in that boundary. Confirm its private
   HTTP/Unix IPC works entirely inside the private network namespace and the
   native relay reaches only the mounted model socket. Confirm static config is on
   a read-only mount and verify genuine native tool execution through the
   selected gateway. Do not use `/healthz` or a synthesized model list as proof
   of inference. Test wrong token/model/path, cancellation and unavailable host.
   Successful configuration rendering does not establish that native IPC,
   socket activation or the private filesystem bindings work on the target.

6. Exercise a child that creates a new process session (`setsid`) and remains alive.
   Cancel/fence/kill the coordinator and verify no populated tool cgroup before
   a checkpoint/recovery receipt is accepted. Test unit/firewall restart and
   nft ruleset reload; the worker must never gain broader network access.

7. Set and verify a **persistent filesystem quota** for workspace/runtime and a
   capacity/backup policy for protected checkpoint storage. CPU/RAM/process and
   output bounds do not prevent disk exhaustion. The module deliberately does
   not guess Btrfs/ZFS/LVM dataset ownership or format a volume. No
   `budget_enforced` receipt claim is valid until the selected host quota and
   inference allowance are actually enforced.

8. For the 3090 route, verify real cold-start/generation, one active model owner,
   desktop coexistence, cancellation, and existing model TTL/unload behavior.
   These host cgroup settings constrain tool CPU/RAM, not GPU VRAM. Do not
   increase the existing 65,536-context/single-slot model merely because local
   requests have no monetary allowance.

The source tests exercise the bridge's fixed command construction, metadata
binding, descriptor-based handoff, symlink refusal, mandatory cleanup proof and
admission argument construction. They emulate no running host services and do
not establish live host isolation.

## Rollback and recovery

Stop admissions first, then stop `lanectl-resident-episode.service`; inspect the
tool cgroup and run the protected cleanup hook if the unit was interrupted.
Keep unknown executions fenced until `resident recover` establishes cleanup.
Preserve the selected receipt log, checkpoint objects and workspace backup.

Revoke the resident's peer/provider credential and route grants, then disable
the module or restore the previous reviewed host generation. The module starts
no GPU engine, changes no desktop-user groups, and owns a distinct firewall
table. Do not delete its firewall rules while a worker is running. Do not revert
fencing/receipt state to make an old wake appear new. Existing peer clients and normal
desktop serving remain under their original owner.
